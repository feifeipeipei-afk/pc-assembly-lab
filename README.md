# 计算机组装、维护与维修 · 教学考核平台

面向职业院校《计算机组装、维护与维修》课程的**通用教学与考核工具**。

一套系统把「平时刷题 → BIOS 设置模拟 → WinPE 装机维护模拟 → 实操现场评分」串成一条完整的教学评链路，
学生从统一入口进入，成绩自动汇总为课程总评，教师开箱即用。

- **不需要装机房硬件**：BIOS 设置与 WinPE 装机维护全程在浏览器里仿真操作，一台教师机 + 学生机浏览器即可开考
- **不需要教师手工判分**：模拟器成绩由服务端按评分细则自动判定，教师只需录入现场实操分
- **理论 + 实操一体化**：题库、模拟器、实操分共用一个花名册和一套成绩库，总评一键导出

> 适用课程：《计算机组装、维护与维修》《计算机组装与维护》《计算机硬件组装与调试》等。
> 部署与考前操作细节见 [`使用说明-统一考试系统.md`](./使用说明-统一考试系统.md)。

## 系统由哪几块组成

| 模块 | 入口 | 占比 | 谁来评 |
|---|---|---|---|
| 理论刷题 | `/` | 平时分 50% | 系统（等级自动折算） |
| BIOS 设置模拟 | `/sim/bios` | 12.5% | 系统（按操作事件重放判分） |
| WinPE 装机维护模拟 | `/sim/winpe` | 12.5% | 系统（按操作事件重放判分） |
| 实操装机（现场） | 不在此系统 | 25% | 教师现场评分后录入 |
| **统一入口（学生从这里进）** | `/portal` | — | — |
| 教师后台 | `/admin` | — | 成绩总表在「技能考试成绩」页 |

三个模块共用同一份学生花名册（姓名 + 班级），学生一次登录即可在三个模块间切换，成绩自动归集到同一个人。

---

## 总评怎么算

```
总评 = 平时分 × 50% + 考试分 × 50%
考试分 = 实操装机 × 25% + BIOS 模拟 × 12.5% + WinPE 模拟 × 12.5%
```

- **平时分**：由刷题系统的等级折算分（占主导）与竞技场三星加成构成，0~100 分制
- **实操装机**：教师现场评分后在后台「技能考试成绩」页行内录入，未录入时按 0 分计并标红提醒
- **BIOS / WinPE**：各自归一化到百分制后按 12.5% 计入，未考显示红色「未考」
- 支持「**冻结平时分**」：把当前平时分定格为快照，此后学生刷题不再影响总评，保证已核算成绩稳定

模拟器的考试时长、切屏阈值、考试时段窗口、评分细则版本都可在后台配置或按需扩展，无需改代码。

## 模块一：理论刷题

学生端 `/`，教师端 `/admin`。

### 学生端

- **花名册模式**：老师导入班级学生名单后，学生只能从名单中选择自己的姓名登录，防止乱注册、乱填名字捣乱（可在管理后台关闭，恢复自由注册）
- **正式考试**：随机抽取 50 道题，限时 90 分钟，计入班级等级榜
- **考试管控**：老师可设定考试时段（窗口外禁止开考，进行中的不受影响）与次数上限；正式考试中切屏/切出会被静默记录并在管理端标红
- **分类练习**：按分类自选题量（10/20/30 题），不限时，答完立即显示对错与解析，同样获得经验
- **错题本**：自动汇总考试与练习中的错题，展示正确答案与解析，支持一键「错题重练」
- **经验与等级系统**：答对得经验，王者荣耀式 30 级段位（青铜Ⅳ → 最强王者）；首页等级卡片展示段位、升级进度、班级排名与平时成绩折算分；升级触发庆祝动画
- 键盘操作：`A`–`D` 选择答案、`←`/`→` 切换题目、`Esc` 关闭弹窗
- 交卷后展示成绩圆环、本轮经验结算、分类正确率统计和错题回顾；历史成绩可点击回看详情
- **⚔ 战斗竞技场（课间训练专用）**：火焰纹章风格战斗画面，答题即出招，详见下节

### ⚔ 战斗竞技场（PVP / PVE）

课间训练专用模式，不计入考试；可在管理后台一键关闭（`battle_enabled` 开关）。答对即攻击对手（连击 ≥3 触发「会心一击」演出），PVE 闯关答错会被 Boss 反击掉血。

- **🏰 闯关模式（PVE）**：每个题库分类即一关（按分类题量降序编号，当前共 17 关），通关上一关解锁下一关；每关 10 题，按正确率评星（一星 ≥60% / 两星 ≥70% / 三星 ≥90%）
- **🎮 三星加成**：集满三星的关数按占比折算进平时成绩，全部三星最多 **+5 分**（与等级折算分并列展示）
- **👤 影子对战（异步 PVP）**：排位赛随机 10 题成绩录成「影子」，同班同学可随时挑战；影子按对方原题原时间轴实时「出手」，比答对数、同分比用时
- **🎯 训练假人（PVE 热身）**：青铜/白银/黄金三档假人，影子目标递增，不计天梯分
- **🏆 班级天梯榜**：胜 +5 / 平 +2 / 负 +1（输也有参与分），假人不计分
- 战斗中经验照常按防刷分规则发放；断线/刷新后回到战场可续战
- 键盘 `A`–`D` 出招，`←`/`→` 回看战况

#### 战斗画面渲染器（可切换）

战斗画面支持两套渲染器，可在不改动任何战斗逻辑的前提下切换：

| 渲染器 | 说明 |
| --- | --- |
| `dom`（默认） | 原生 DOM + CSS 动画，纯离线零依赖，行为与历史版本一致 |
| `three` | Three.js（WebGL）舞台：切图骨骼角色 + 着色器舞台 + 事件驱动演出（顿帧/特效/镜头/飘字） |

切换方式：在学生端 URL 后加 `?renderer=three`（选择会记到 localStorage，之后一直生效），加 `?renderer=dom` 可切回。WebGL 不可用时会**自动回落**到 `dom`，不会白屏。

- Three.js 以**本地 vendored** 方式引入（`static/vendor/three/`，r186），**不依赖 CDN、不需要联网、无需构建**
- 渲染与动画代码全部分模块放在 `static/js/battle/`，用浏览器原生 import map 加载 ES 模块
- 默认走 `dom` 时**不会下载** Three.js（约 2MB），探测通过后才按需加载
- 战斗视图不可见时不渲染（省电）；离开战斗会释放全部 GPU 资源

`three` 模式的动画体系（`static/js/battle/`）：

- **舞台**（`renderer/`）：StageScene 用 1 个全屏 quad + 片元着色器画天空渐变/网格线/地面条；RendererHost 管帧循环、正交相机、DPR 钳制与 resize
- **角色**（`units/`）：`tools/build_battle_assets.py` 把整图切成部件图集，UnitView 按 rig 定义分层驱动（躯干/头/四肢/武器各自摆动），部件矩形烘进 UV 共用一份材质，待机呼吸分层滞后
- **演出编排**（`anim/`）：Choreographer 把业务事件（命中/会心/连击/影子对手出招）展开成时间轴 —— 突进、命中顿帧（hit-stop）、受击闪白；业务层通过 `battleDispatch` 派发事件，three 活着才消费，否则回落旧 DOM 演出，**两套渲染器互斥、绝不双重演出**
- **特效**（`fx/`）：ImpactFX 维持斩击弧光/命中闪光/冲击环/扬尘的 quad 与粒子池（粒子数受 BUDGET 预算钳制）；CameraDirector 负责命中瞬间的镜头推近与震屏
- **HUD**（`hud/`）：伤害飘字/会心横幅/连击提示仍走 DOM，但由 HudLayer 用 worldToScreen 投影定位到角色头顶，跟随镜头

### 经验与等级规则（防刷分设计）

- 每答对 1 题基础经验 10 点；每天前 15 题足额、16~30 题减半、之后骤减（防考前突击）
- 同一题首次做对得全额；之前做过（无论对错）再对只计 30%，第三次起为 0（防「先乱答看答案再重刷」）
- 升级所需经验随等级递增；达到**合格等级（默认 20 级·星耀Ⅳ，共需 2850 经验）**视为平时成绩合格
- 等级折算平时成绩：1 级 = 0 分，合格等级 = 60 分，满级（30 级）= 100 分
- 经验从系统启用时开始累计，历史答题不回溯发放；「每日」界限按北京时间计算

## 模块二：BIOS 设置模拟（/sim/bios）

`static/sim/bios.html` · 正式考试 **20 分钟 / 100 分** · 评分细则 `bios-v1`

把真机的 BIOS 设置流程完整搬进浏览器：**开机自检（POST）→ 进入 Setup → 按任务清单完成「用 U 盘装系统前的全套配置」→ F10 保存退出即交卷**。
一次进入 BIOS 完成一串连贯的多步骤操作，比逐题问答更贴近真实装机场景。

### 四种固件皮肤，1:1 还原不同年代的机器

| 皮肤 | 对应机型 | 布局与配色 | 进入 Setup / 启动菜单键 |
|---|---|---|---|
| **Phoenix** | 联想笔记本 | 经典蓝底，页签在顶部，帮助栏在右 | `F2` / `F12` |
| **Award** | 技嘉等老主板 | 蓝底，左侧竖排菜单，帮助栏在底 | `DEL` / `F12` |
| **AMI** | 华硕等老主板 | 深蓝底 + 银灰标题栏 | `DEL` / `F8` |
| **UEFI** | 现代图形化固件 | 深色圆角界面，支持鼠标点选 | `DEL` / `F8` |

- 顶栏按真机分三区（左：主板型号 / 中：Setup 标题 / 右：固件版本），老式固件叠加一层极淡的 CRT 扫描线
- 底部帮助栏显示**当前皮肤的实际按键映射**，学生照着提示就能操作，不会因为「到底按 F12 还是 F8」卡住
- **练习模式可自由切换四种皮肤**；**正式考试统一锁定 Phoenix，保证所有考生条件一致**

### 考试要做的操作（评分项一览）

正式考试由服务端下发任务清单（只写"要做什么"，不含判分逻辑），共 15 个评分项、满分 100：

| 评分项 | 分值 | 考查内容 |
|---|---|---|
| 开机自检：识别内存异常并正确处置 | 10 | POST 报 `Memory module in DIMM1 failed`，应先**重新插拔**排查，而非直接换内存 |
| 切换到 Boot 标签页 | 4 | 会用方向键在页签间导航 |
| 进入 Boot Device Priority 子菜单 | 4 | 知道启动项在子菜单里，而不是全局乱翻 |
| 把 U 盘（USB HDD）设为第一启动项 | 10 | 用 `+` / `↑` 调整启动顺序（未进子菜单直接改的只给一半分） |
| 关闭 Secure Boot（安全启动） | 6 | 不关会认不到 U 盘引导 |
| 开启 CSM 或改为 Legacy 启动模式 | 6 | 理解 UEFI/Legacy 兼容模式对装机的影响 |
| 检查并开启 USB Boot | 4 | 必须真的改动过才给分（防"默认值恰好满足"白拿分） |
| 检查并开启 USB BIOS Support | 4 | 同上，侧重于 Advanced 页 |
| 把系统日期校正为今天 | 6 | 按 `MM/DD/YYYY` 格式改对 |
| 把系统时间校正（误差 ≤5 分钟） | 6 | 误差 30 分钟内给一半分 |
| 设置 Supervisor Password 并完成二次确认 | 8 | 与真机一致，要输两遍；未二次确认给一半分 |
| 确认 Password on Boot 为 Disabled | 4 | 避免装机后开机卡在密码输入 |
| 用 F12 启动菜单临时从 U 盘启动 | 8 | 一次性启动菜单，不改 BIOS 里的启动顺序；选错设备给一半分 |
| 故障判断：拔掉硬盘开机报什么错 | 10 | 自检报 `No boot device`，考故障现象与原因对应 |
| **F10 保存并退出（Exit Saving Changes）** | 10 | ★ 整场考试的最后一步，保存即交卷；只保存没退出给一半分 |

### 判分设计上的两个细节

- **任务清单顺序 = 真实操作顺序**，`F10 保存并退出` 固定排在**最后一步**——它在正式考试里等于交卷，若排在中间会导致学生做到一半就把整场考试提前结束；F10 确认框也会提示「这是最后一步」
- **依赖关系与部分分**：如「把 U 盘设为第一启动项」要求先进入 `Boot Device Priority` 子菜单，直接用全局快捷键改状态说明没走对流程，只给部分分；「默认就是 Enabled」的项（如 USB Boot）必须发生过修改事件才给分，防止什么都不做白拿分

### 除正式考试外还保留

- **练习模式**：不计分、不限次，可自由切换四种皮肤，内置按皮肤差异化的练习题库
- **UEFI 时代考点**：Secure Boot / Fast Boot / CSM / TPM 2.0、`H/W Monitor` 硬件监控页（温度、转速、电压）
- **错误操作的后果演示**与故障判断小测（菜单里可直接进入）

## 模块三：WinPE 装机维护模拟（/sim/winpe）

`static/sim/winpe.html` · 正式考试 **30 分钟 / 100 分** · 评分细则 `winpe-v2`

从**U 盘引导 → PE 加载 → 进入 PE 桌面 → 分区 / 装系统 / 硬件检测**，完整还原装机维护的实操流程。
进入考试后自动打开服务端下发的**考试任务清单**，学生一眼看清本场要做哪些操作。

### 仿真的系统环境

- **引导链路**：开机 → 启动菜单选 U 盘 → PE 加载进度 → 进入桌面（每个环节都有对应的操作事件）
- **桌面 / 任务栏 / 窗口边框**按 Windows 10 PE 风格仿真（开始按钮、搜索框、托盘、显示桌面、浅色标题栏）
- **右键菜单**：桌面空白处右键（刷新 / 打开工具 / 显示设置）、桌面图标右键（打开 / 管理员运行 / 属性）、DiskGenius 分区上右键（删除当前分区 / 格式化 / 设为活动 / 属性）
- **图吧工具箱**按原版重做：左侧分类栏、顶部跨分类搜索、工具卡片网格、底部状态栏

### 考试要做的操作（评分项一览）

共 13 个评分项、满分 100：

| 评分项 | 分值 | 考查内容 |
|---|---|---|
| U 盘引导进入 WinPE | 6 | 启动菜单选 U 盘 → 等待 PE 加载 → 进入桌面 |
| 快速分区 · 基础 | 15 | **MBR / 3 个分区 / C 盘 100GB / 4K 对齐 4096 扇区**（5 个要点按比例给分） |
| 快速分区 · 进阶 | 14 | **GUID / 4 个分区 / 勾选 ESP+MSR / 80GB+200GB**（7 个要点按比例给分） |
| 删除 E 盘并确认 | 6 | 删除分区并在确认框中确认 |
| 安装系统：引导分区与安装分区均选 C 盘 | 11 | 选 `install.wim`，两个分区都选 C，等待进度完成 |
| CrystalDiskInfo：健康结论「良好」且 C5 原始值为 0 | 6 | 会读 SMART 信息，判断硬盘健康状态 |
| CrystalDiskMark：C 盘 / 5 次 / 1GiB / All 完整测速 | 8 | 会配置测速参数并跑完 |
| 显示器坏点检测：五色全看 + 正确报告 | 6 | 依次看红绿蓝白黑五种纯色，找出亮点/暗点 |
| CPU 烤机：Extreme / 全线程 / ≥60 秒 | 4 | 真实秒计时，跑满 60 秒再停止提交 |
| **AIDA64：硬件信息检测与报告** | 6 | 设备树 + 计算机汇总 + 传感器页，读出主板型号 / 内存容量 / CPU 温度并提交报告 |
| **MemTest：内存完整性检测** | 6 | 可运行的内存检测，进度条 + Pass/Errors 计数，须跑满 ≥1 轮且 0 错误 |
| **键盘测试：按键响应检测** | 6 | 真实捕获按键并高亮键盘图，须依次按下 A、S、D、F、空格 |
| **鼠标测试：按键与滚轮检测** | 6 | 真实捕获左键 / 右键 / 滚轮 / 双击 |

> 加粗的四项是 `winpe-v2` 新增：把图吧工具箱里原先「只有图标、点开只弹提示」的工具补成**真实可操作、可计分**的检测项。
> 为保持满分 100，原有各步分值等比压缩；**`winpe-v1` 冻结保留**，此前考过的成绩不受影响。

### 分项评分的实现细节

- 分区分值按**要点数等比给分**（基础题 5 个要点、进阶题 7 个要点，错一项扣对应比例），避免"差一点就全丢"
- 快速分区判定**遍历历史操作**取最好一次——学生可能先做基础题再做进阶题，只看最后一次会误判基础题没做

## 模块四：教师端技能考试成绩

后台 `/admin` → **「技能考试成绩」** 标签页，是这门课的成绩总表。

### 总表

一行一个学生，12 列：`排名 / 学号 / 姓名 / 班级 / 平时分 / BIOS / WinPE / 实操装机 / 考试分 / 总评 / 切屏 / 操作`

- **实操装机**列是输入框，**直接在格子里填分回车即可保存**；没录过时输入框标红，该项按 0 分计

| 操作 | 作用 |

### 单人明细

点姓名或「明细」打开抽屉，可以看到：

- 该生 BIOS / WinPE 的**逐项得分**（哪一项拿了、哪一项没拿、提示是什么）
- **操作时间轴**（每一步在第几秒做了什么）
- 切屏次数、用时、交卷时间
- **作废本次考试**按钮：作废后该生可重考，原成绩不再计入总评

> 学生申诉「我明明做了」时，直接看时间轴即可核对；教师改分全部记入审计日志。

## 判分可信度与防作弊

模拟器的分数不由前端决定，改前端 JS 拿不到分：

- **前端不判分**：学生端只上报「做了什么」（事件流），分数由服务端按事件**重放状态**后逐项判定
- **服务端重放**：`state` 每次改动都会自动产生一条事件（用 Proxy 拦截，不会漏埋点），服务端按顺序重放得到最终状态再判分
- **默认值不算分**：像「USB 启动默认开着」这种，必须学生真的动手改过才给分
- **限考 1 次**：靠数据库**部分唯一索引**兜底，并发请求也挡得住；练习模式可无限次；教师作废后约束自动解除且记录保留可审计
- **超时事件不计分**：超过考试时限之后上报的事件会被裁掉；倒计时以**服务端时间**为准，学生机时钟不准不影响
- **操作时间轴留痕**：事件流哈希入库，教师端可逐秒回看，改分全部记审计日志
- **切屏记录**：考试中切屏/切出被静默记录，教师端按阈值标色（1~2 次橙色、3 次以上红色）

成绩**绝不写入**刷题系统的 `quiz_sessions` 表——模拟器独立使用 `sim_sessions / sim_events / sim_scores / sim_score_log` 四张表，与既有业务零交集，不会污染教师端数据页与导出表。

### 课堂局域网部署要点

学生机访问的是**教师机的内网 IP**，不是 localhost：

```
http://192.168.x.x:5001/portal
```

若学生机打不开，九成是 Windows 防火墙拦了端口，管理员 PowerShell 放行一次即可：

```powershell
netsh advfirewall firewall add rule name="QuizExam5001" dir=in action=allow protocol=TCP localport=5001
```

**考前务必先备份数据库**（同目录下的 `quiz_app.db`）。

## 管理后台

- **成绩列表**：按姓名/班级搜索、按类型（考试/练习）筛选、真分页（20 条/页）、删除记录；正式考试记录显示**切屏次数**

- **⟳ 同步题库**：题库文件更新后点击即可生效，无需重启服务器
- **⚔ 战斗竞技场开关**：一键开启/关闭学生端竞技场入口
- **考试时长 / 切屏阈值 / 考试时段窗口**：模拟器参数在后台可调，不用改代码
- 修改管理密码、退出登录、登录失败限流（连续 5 次锁定 1 分钟）
- Excel 导出：成绩汇总（仅考试，含切屏次数）+ 详细记录（含练习，标注类型与范围）+ 平时成绩（等级折算）

## 安全须知

- 首次启动默认管理密码为 `admin123`，**登录后请立即在后台右上角「修改密码」中更换**
- 密码以哈希存储于数据库 settings 表，忘记密码可删除数据库中 `admin_password_hash` 记录后重启（恢复默认）
- 服务器默认以非调试模式运行；调试模式会暴露交互式控制台，仅限本机调试使用
- 面向课堂局域网使用；如需公网部署，请置于 HTTPS 反向代理之后并使用 waitress/gunicorn 等 WSGI 服务器

## 常见问题

| 现象 | 原因 / 处理 |
|---|---|
| 学生机打不开 `/portal` | 教师机防火墙没放行端口；或用了 localhost 访问 |
| 提示「你已参加过…」 | 模拟器限考 1 次。确认要重考：后台 → 技能考试成绩 → 该生明细 → 作废 |
| 倒计时与学生机时钟不一致 | 倒计时以**服务端时间**为准，学生机时间不准不影响 |
| 交卷后某项 0 分，但学生说做了 | 看该生明细里的操作时间轴；只有真实产生事件才算 |
| 总评里平时分一直在变 | 点「冻结平时分」定格快照 |
| 控制台报 `attempt to write a readonly database` | 杀毒软件短暂占用了 `-wal` 文件；系统已内置重试，一般会自动成功 |
| 想清空所有模拟考试记录重来 | `py reset_sim_data.py` 先演练，加 `--yes` 真正执行（只清 4 张 sim_\* 表，不动刷题数据） |
| 本地生成了哪些文件 | `quiz_app.db`（数据库）与 `.secret_key`（会话密钥），均已加入 `.gitignore` |

> 更多部署与考前检查清单，见 [`使用说明-统一考试系统.md`](./使用说明-统一考试系统.md)。
